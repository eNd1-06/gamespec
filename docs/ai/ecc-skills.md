# GameSpec AIチーム・第1段階のSkills

## 構成と利用方法

ECC由来の3 Skillsを、リポジトリ内の `.agents/skills/` に置く。
ECC全体、Hooks、MCP、外部自動実行設定、追加依存、自動委任は導入しない。
共通ルールは [AGENTS.md](../../AGENTS.md)、固定出典・全文レビュー結果は
[ecc-sources.md](ecc-sources.md)、MIT全文は [ECC-LICENSE](../../third_party/ECC-LICENSE) を参照する。

Codexをこのリポジトリのルートで起動し、次のように明示的に呼び出す。
更新が見えないクライアントでは、新しいセッションを開始して一覧を確認する。

```text
$ecc-seo マウスカテゴリのcanonicalとJSON-LDを読み取り監査してください。
修正せず、コード上の事実と未検証の仮説を分けてください。

$ecc-frontend-patterns app/mice/compare/page.tsxをレビューしてください。
編集せず、同梱Next.jsガイドを根拠に状態管理とアクセシビリティを確認してください。

$ecc-verification-loop 現在の変更を基準コミットと照合して検証してください。
実行した確認と未実施の確認を区別してください。
```

通常の依頼では自動発火しない設定とする。3つとも `agents/openai.yaml` に
`allow_implicit_invocation: false` がある。
説明にSkill名を挙げることと、実際にそのSkillを読み込むことを混同しない。
この段階ではClaude Code側のSkill自動認識は対象外。
既存の `CLAUDE.md` → `AGENTS.md` 参照は維持する。

## チームでの使い分け

SEO担当は根拠付き監査、開発担当は同梱ガイドに沿った変更、QA担当は検証の証拠を扱う。
これらは作業観点であり、並列エージェントを自動起動する設定ではない。
引き継ぎには対象・基準コミット、変更ファイル、受け入れ条件、検証結果と未確認事項を含める。
プロンプトやSkillの読み取り専用指示は、サンドボックスや接続ツールの権限を変更しない。

## 第1段階の検証記録

開始時のGitHub `master` とローカルHEADは、ともに
`140b04030ef58e548c66123b058ef028121ce410`。
GitHub APIで全ブランチと直近最大30件の全状態PRを確認し、ブランチはmasterのみ、PRは0件だった。
シェルの `git fetch origin master` はプロキシ接続エラーで失敗したため、
最新状態の確認・公開にはGitHub接続ツールを使う。
ネットワーク許可付きの読み取り専用 `git ls-remote origin refs/heads/master` でも同じSHAを確認した。

| 確認項目 | 状態 | 根拠・理由 |
| --- | --- | --- |
| 上流3 SkillsとLICENSEの全文レビュー | PASS | 固定SHAから取得し、全節・コード例・末尾を確認。詳細は出典記録 |
| 形式・リンク・ポリシー・ライセンス | PASS | 既設PyYAMLで6ファイルを解析。名前・説明・固定SHA・真偽値false・全相対リンクを確認。MIT全文と既存Next.jsルールは原文とバイト一致 |
| クライアントのSkill一覧認識 | PASS | Codex 0.163.0のapp-server `skills/list` をforceReload付きで実行。ルートと `app/mice` の各cwdで3件ともrepoスコープ・enabled、errorsは0件 |
| 明示呼び出しの静的確認 | PASS | 3件の名前と `$skill-name`、default_prompt、説明、対象ファイルの対応を確認 |
| 明示呼び出しの実モデル試験 | BLOCKED | 下記の実行環境・外部送信に関する制限。Skill読み込み後のモデル応答は取得できていない |
| 通常依頼での非発火設定 | PASS | 3件ともYAML上の `allow_implicit_invocation` は真偽値false。モデル実行時の非発火は別項目 |
| 通常依頼での非発火の実モデル試験 | NOT RUN | 実モデル試験の外部送信が承認されていないため未実施 |
| アプリbuild・型・lint | NOT RUN | 文書・Skillのみの変更。アプリと依存は変更しない |
| アプリ単体テスト・E2E | NOT RUN | testスクリプトとE2E基盤がなく、この変更では追加しない |
| 本番SEO・実ユーザー性能・ブラウザ操作 | NOT RUN | 今回はSkill導入の検証。本番アクセス・デプロイは行わない |
| 差分・権限・依存の増加確認 | PASS | `git diff --check`、基準からの差分、未追跡一覧を照合。変更は本PRの10ファイルのみ。アプリ・データ・依存・ロックファイル・既存アプリ設定・CLAUDE.mdは変更なし |

認識試験は一時的な `CODEX_HOME` をリポジトリ外に置き、個人の設定を変更せずに行った。
`skills/list` に渡したパラメータは次のとおり。これは一覧認識試験であり、モデル呼び出しではない。

```json
{"cwds":["/workspace/gamespec","/workspace/gamespec/app/mice"],"forceReload":true}
```

明示呼び出し試験では、3つの `$skill-name` を指定して各本文を読み、
各Skillの安全上の注意を報告するよう依頼した。編集・build・外部操作・委任は禁止した。
`codex exec --ephemeral --ignore-user-config --sandbox read-only --json` に
実行時限定の機能制限を渡し、リポジトリの設定ファイルは追加していない。
初回は実行状態の保存先が読み取り専用で起動失敗。
一時領域へ切り替えた試行では `Operation not permitted`、HTTPSへの切り替え後も
接続失敗が続き、応答を取得できずタイムアウトした。
続くネットワーク許可付き試行は自動承認審査が実行前に拒否した。
拒否理由は、Skillや作業コンテキストを外部APIへ送信し得る一方で、
その送信先・範囲が明示的に許可されていないこと。迂回はしていない。
実モデル試験は、送信範囲と送信先への承認が得られた環境で再実施する必要がある。

判定: 第1段階のファイル追加と一覧認識は確認済み。実モデルによる明示呼び出し・
非発火は未検証のため、Draft PRとしてレビューに回す。全検証完了・マージ可能とは判定しない。

## 再検証と残る制限

- 各 `SKILL.md` の名前とディレクトリ、説明、MIT、固定SHAを確認する。
- YAMLを実際に解析し、`allow_implicit_invocation` が文字列でなく真偽値falseか確認する。
- リポジトリルートからCodexのSkill一覧を更新し、3件のパス・名前・ポリシー・エラーを確認する。
- 上記の呼び出しを読み取り専用の試行として実行する。実行できなければBLOCKEDと理由を残す。
  一覧認識の成功だけでモデルの呼び出し成功を主張しない。
- 通常の依頼で非発火かを別に確認する。静的設定の確認だけならその範囲を明記する。
- `git diff --check` と開始コミットからの全変更を確認する。
  `app/`、`data/`、依存、ロックファイル、既存アプリ設定が変わっていないことを確認する。

クライアントのバージョン・管理ポリシーによる差、指示遵守のばらつき、
将来の上流・Next.js仕様の変更は残る。静的検査とSkill認識は、
SEO成果、アプリの品質、すべての脆弱性がないことを保証しない。
