# GameSpec SEO audit

ECC `seo` のGameSpec向け派生版。出典・変更点は
[出典記録](../../../docs/ai/ecc-sources.md)、ライセンスは
[ECC-LICENSE](../../../third_party/ECC-LICENSE) を参照する。

## 入力と境界

1. ルートの `AGENTS.md` を読み、対象カテゴリ・ページ種類・監査か修正かを確認する。
2. 既定は読み取り監査。修正は現在のタスクで依頼された範囲に限る。
   このSkillはパッケージ導入、外部スクリプト実行、公開操作を許可しない。
3. Next.jsの関連ガイドを `node_modules/next/dist/docs/` で確認する。
   同梱ガイドがなければ対象バージョンの公式ドキュメントを確認する。
4. コード上の確認、実行時の測定、未確認の仮説を分ける。
   Search Consoleや本番計測にアクセスしていなければ、その結果を推測しない。

## 監査手順

### URL・クロール・インデックス

- `app/robots.ts`、`app/sitemap.ts`、カテゴリの `layout.tsx`・`page.tsx` を読む。
- 一覧、`[slug]`、`compare`、`vs/[pair]`、ランキング、ガイドを区別する。
- canonical・OGのURL・sitemapの公開URLを照合し、URL形式と内部リンクを確認する。
- `compare?a=...&b=...` のクエリ違い、vsの逆順・同一製品・不明slugは
  重複や境界条件の候補として調べる。期待動作を確認せず一括変更しない。
- robotsのクロール制御とnoindexを混同しない。非公開化の手段ともみなさない。
- `lastModified` が実際の更新根拠に対応するか確認する。
  sitemapにあるだけでインデックス済みとは判断しない。

### 検索意図とページ内容

- ページごとの主な検索意図、title、description、H1と見出し階層を確認する。
- 日本語では英語の文字数目安を必須条件にしない。明瞭さと実際の内容を優先する。
- 年表記・レビュー表現・推薦理由が事実に基づくか確認する。
  見栄えのために現在年へ更新しない。
- 商品詳細↔vs↔カテゴリ間のリンク、リンク切れ、薄い類似ページを調べる。
- 検索需要や競合性は裏付けのあるデータがなければ仮説と明記する。
  キーワードの詰め込みや検索順位の保証をしない。

### 構造化データ

- 実際の表示と `Product` / `Offer` / `BreadcrumbList` 等を照合する。
- `data/*.ts` の価格、通貨、仕様、商品URLと出力が一致するか調べる。
  参照価格を現在価格と断定せず、在庫・評価・レビュー件数を捏造しない。
- FAQ等のマークアップは表示内容と整合させる。
  構文の妥当性とGoogleの検索結果表示の適格性を分け、適格性は最新公式資料で確認する。
- JSON-LDの文字列を安全に埋め込む方法は同梱の `02-guides/json-ld.md` を参照する。
  `JSON.stringify()` 単独を、外部由来の値に対する安全性の保証としない。

### パフォーマンス

- JS量、画像サイズ・寸法、フォント、レイアウト移動を確認する。
- LCP・INP・CLSは測定条件と実測値を報告する。コード読解だけで数値を出さない。
  ラボ計測と実ユーザー計測を分け、測定なしなら `NOT RUN` とする。

## 出力

各指摘を次の形式で記録する。

```text
優先度: HIGH / MEDIUM / LOW
対象: URL、ファイルと行、対象コミット
確認区分: コード確認 / 実測 / 仮説
根拠: 確認した内容と出典（秘密値を含めない）
影響: 想定される影響。未検証なら明記
提案: 最小の修正案と受け入れ条件
検証: PASS / FAIL / NOT RUN / BLOCKED / N/A と理由
```

監査結果と実装済みの変更を混同しない。必要なら明示的に
`$ecc-frontend-patterns` または `$ecc-verification-loop` を併用する。
他のECC Skills・Agentsは導入済みと仮定しない。
